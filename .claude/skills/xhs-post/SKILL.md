# 小红书笔记生成

将一个想法或选题转化为符合小红书平台特性的笔记。本账号定位：科技AI、web3、金融经济、商业财经、社会学、生活感悟——风格是**理性但亲和的知识分享者**，不用"姐妹们/家人们"式喊麦，靠信息密度和洞察留人。

## 输入

一个想法描述，或 `ideas/` 下的选题文件路径。如果 `ideas/` 里有对应选题文件，先读它，以其中的核心观点和素材要点为准。

## 平台规则

- **标题**：≤20 字，必须有钩子（数字、反差、悬念、利益点），可带 1 个 emoji。给出 3 个候选，风格各异（干货型 / 观点型 / 悬念型）。
- **正文**：600-1000 字。第一句必须承接标题、给出继续读的理由。短段落（每段 ≤3 行），段间用空行或 emoji 符号（✅ 📌 💡 ⚠️ 👉）做视觉分隔。列表和分点优先于大段文字。
- **语气**：口语化但不轻浮，像懂行的朋友在分享。财经/科技内容要有具体数字、案例、结论，不空谈。
- **结尾**：一个互动引导（提问式，引导评论区讨论）。
- **标签**：4-6 个话题标签，混合大流量词（如 #AI #副业）和精准长尾词。
- **封面文案**：给出封面图上的大字文案（≤12 字）+ 副文案（≤20 字），供制图用。

## 排版规范

小红书编辑器是**纯文本**，不支持 markdown——加粗、标题符号发出去就是乱码字符。排版全靠 emoji、符号和空行：

- **移动端行宽**：手机一行约显示 20 字。长句在 20 字内制造停顿，避免一句话占满三行。
- **段落**：每段 1-3 行，段与段之间空一行。全文看起来要"透气"，大段文字直接劝退。
- **视觉锚点**：默认靠空行 + 短段落 + 叙述流转场；emoji 只做局部点缀（提醒用 ⚠️、单处强调用 💡 之类），正文总量 ≤10 个。**禁用"每节一个 👉/📌 小标题"的 emoji 骨架**——那是平台上 AI 批量笔记的标准形态，等于自带识别标签（2026-07 复盘结论）。
- **强调**：没有加粗可用，重点靠——单独成段、或用「中式引号」框住关键词。
- **数字分点**：确有并列清单时可用 1️⃣2️⃣3️⃣ 或 "1. " 编号（方便截图收藏），一篇最多 1 组；能用叙述讲清的不列点。
- **首行**：编辑器里正文第一行会出现在信息流摘要里，第一行必须是钩子，不要放 emoji 装饰或空话。

## 整套图生成（封面 + 内容图）

**前置条件：仅在用户明确定稿文字后执行。**修稿阶段严禁生成任何图片（不写图片 html、不渲染）——文字改一版图就作废一版，等定稿再出图。

每篇笔记产出一套 3:4 图（1242×1656），全部用 HTML 模板渲染，保证中文清晰、账号视觉统一。

**主题选择**（按选题领域轮换，同一篇内只用一个主题）：
- `tech`（暖白墨绿风：米白底 + 碳墨 + 深松绿）：科技AI / web3
- `finance`（米白纸感 + 藏蓝 + 金）：金融经济 / 商业财经
- `warm`（奶油底 + 暖橘）：社会学 / 生活感悟

**流程**：
1. 从 `templates/<主题>/cover.html` 和 `content.html` 复制结构，填充本篇内容，存到主题文件夹：`cover.html` + `page2.html`…`pageN.html`（页码标 02/0N 起）。
2. 整套 4-6 张：封面（钩子）→ 中间每页只讲一个信息点（正文块/清单块/数据块三选一二，别堆满）→ 末页固定为互动提问 + 关注引导（+ 金融内容加"不构成投资建议"）。
3. 图上文字比正文更凝练——图是收藏点和截图传播物，不是正文的复制。
4. 渲染：`bash templates/render.sh <主题文件夹>`（无头 Chrome）。
5. **渲染后必须逐张 Read 检查 PNG**：重点看底部元素是否被裁切、标题换行是否难看（引号用「」，每行 ≤7 字大标题）。超高就缩字号/边距重渲染。

## 去AI化（强制）

严格遵守项目 CLAUDE.md 的"叙事与受众规范"和"去AI化写作规范"——规范本体和全部阈值（金句配额、段落节奏、细节等）以 CLAUDE.md 为准，此处不复述。小红书特有注意项——emoji 骨架已在排版规范中禁用，全篇要像真人在聊天里把一件事讲完，而不是一份被排版过的清单。初稿完成后按两份规范自查一遍再交付。

**结构反模板**：动笔前翻看 `xhs/` 下最近 2-3 篇 content.md，本篇开场类型和骨架必须与上一篇不同（轮换菜单见 CLAUDE.md"结构反模板"）。emoji 分点符号体系也别篇篇一样——上篇用 ✅ 这篇可以换 1️⃣ 或纯空行分段。

## 红线

- **交付前必须按 `content-review` skill 的小红书一节做合规扫描**（含标题、标签、封面文案）。特别注意：加密货币/web3 相关词在小红书一律不出现，科普语境也不行——2026-07 首篇实测被判"仅自己可见"。
- 不用绝对化用语（"最""第一""必赚"），金融内容不做收益承诺、不构成投资建议（文末可加一句风险提示）。
- 不堆砌 emoji（正文总量 ≤10 个）。
- 敏感话题（政策、监管）只陈述事实和公开信息。

## 输出

写入 `xhs/<YYYY-MM-DD-主题slug>/content.md`，结构：

```markdown
# 标题候选
1. ...
2. ...
3. ...

# 封面文案
主文案：...
副文案：...

# 正文（发布版，纯文本可直接粘贴）
...（不含任何 markdown 语法，排版按"排版规范"用 emoji/空行完成，标签直接附在正文末尾）

# 话题标签
#... #... #...
```

"正文（发布版）"必须是打开小红书就能整段复制粘贴的最终形态。

如果该主题文件夹已存在，直接更新其中的 content.md。生成后简要说明选题角度是什么、为什么这样切。
