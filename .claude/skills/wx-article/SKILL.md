# 公众号文章生成

将一个想法或选题转化为公众号深度长文。本账号定位：科技AI、web3、金融经济、商业财经、社会学、生活感悟——公众号是三个平台里**最深度**的阵地，读者期待完整的逻辑链和独立观点，而非资讯搬运。

## 输入

一个想法描述，或 `ideas/` 下的选题文件路径。如果 `ideas/` 里有对应选题文件，先读它，以其中的核心观点和素材要点为准。

## 平台规则

- **标题**：≤30 字，给出 3 个候选（观点冲突型 / 利益点型 / 故事悬念型）。不做震惊体标题党，但要有张力。
- **摘要**：≤50 字，显示在转发卡片上，决定转发后的打开率，单独打磨。
- **篇幅**：1500-3000 字，按选题信息量定，不注水。
- **结构**：
  - 开头 150 字内抛出核心矛盾或反常识结论，留住人；
  - 正文用 3-5 个小标题分节，每节一个递进的论点；
  - 论证靠具体：数据、案例、时间线、对比，少形容词；
  - 全文安排 1-2 句可被单独摘出转发的"金句"（放在情绪高点，供金句卡选用）——**不要每节都有**，其余小节平收，金句过密是 AI 文指纹；
  - 结尾：收拢观点 + 一个开放式问题引导留言 + 引导关注/星标。
- **语气**：冷静、有判断、第一人称视角。敢下结论，但结论跟着论据走。
- **配图建议**：在正文中用 `[配图：描述]` 标注 2-4 处建议配图的位置和内容。

## 排版规范

产出为标准 markdown，定稿后由 `scripts/md2wechat.py` 转成公众号富文本（见"发布转换"节），只用该转换器支持的语法子集：

- **段落**：每段不超过 5 行（手机一行约 18-20 字），段间空行。开头三段尤其要短。
- **小标题**：用 `##` 二级标题，全文 3-5 个，标题是观点句不是名词短语（"补贴一停，需求就露馅了" 而非 "市场分析"）。
- **加粗**：每屏（约 300 字）至少一处 `**加粗**` 作视觉锚点，加粗的是结论句而非随机词组；全文加粗不超过 10 处，泛滥等于没有。
- **引用块**：`>` 用于金句、数据来源、他人观点三种场景，一节最多 1 处；其中金句类引用与 CLAUDE.md 金句配额共享额度（不许每节末尾都挂一条）。
- **分割线**：`---` 只用于正文与结尾互动区之间，正文内不用。
- **配图**：`[配图：描述]` 占位放在小节开头或情绪节点，不要连续两段都是图。文末附"配图生图 Prompt"一节——为每处占位写一条可直接粘贴到生图工具（即梦/Midjourney 等）的完整中文 prompt：画面主体 + 构图 + 风格 + 色调 + 比例（公众号横图 16:9 或 3:2），画面内不出现文字（AI 生图文字易错，需要文字的图改用 HTML 模板截图方案）。
- **列表**：并列信息才用 bullet，全文 bullet 组上限以 CLAUDE.md 去AI化规范为准。
- **不用**：表格、脚注、多级嵌套列表——转换后在手机上都很难读。

## 配图流水线

**前置条件：仅在用户明确定稿文字后执行。**修稿阶段严禁生成任何图片（不写图片 html、不渲染）——金句、标题都可能在修稿中变化，等定稿再出图。

排版型图（封面/金句卡/时间线）用 HTML 模板渲染，与小红书同一视觉体系；照片/插画感的概念图走生图 prompt（见"排版规范-配图"）。

**模板**（`templates/` 目录，文件名后缀 `_宽x高` 决定渲染尺寸）：
- `cover_2350x1000.html`：头条封面 2.35:1。主文案必须居中（微信会从中心裁 1:1 做次条/分享图），每行 ≤12 字。
- `quote_1800x1013.html`：金句卡 16:9，放正文情绪高点后，选全文最可转发的一句。
- `timeline_1800x1013.html`：时间线信息图 16:9，4-6 节点、上下交替、节点文案宁短勿折行（孤字换行必须改文案或加宽 .tag）。

**换色**：所有模板用 CSS 变量 `--accent` 控制主题色，按领域切换——科技AI/web3 墨绿 `#1E5C4F`；金融财经 藏蓝 `#1A2B4A`（辅金 `#B8912F`）；社会学/生活 暖橘 `#E07A3F`。米白底 `#F6F3EC` 不变。

**流程**：复制模板到 `wx/<主题文件夹>/` 填充 → `bash templates/render.sh <主题文件夹>` → **逐张 Read 检查 PNG**（裁切、折行、1:1 安全区）→ 在 article.md 配图节登记文件名。

## 发布转换（定稿后，md → 公众号富文本）

article.md 是唯一事实源，不手动过 mdnice 等在线转换器。定稿（含出图）后执行：

```bash
python3 .claude/skills/wx-article/scripts/md2wechat.py wx/<主题文件夹>/article.md
```

生成同目录 `article_wechat.html`（内联样式，品牌墨绿配色）：浏览器打开 → 点"复制全文" → 公众号编辑器粘贴 → 在虚线占位块处插入配图并删除占位块。

- 脚本只读取 `# 正文` 一节，标题候选/摘要/配图 prompt 等工作区块不会混入。
- 修改稿件一律改 md 后重跑脚本，不直接编辑生成的 html。
- 首次在新文章上使用后，粘贴到公众号后台预览一眼，确认样式无丢失再群发。

## 去AI化（强制）

严格遵守项目 CLAUDE.md 的"叙事与受众规范"和"去AI化写作规范"——规范本体和全部阈值（金句配额、细节、比喻等）以 CLAUDE.md 为准，此处不复述。公众号特有注意项（长文是 AI 腔重灾区）：小标题不用"一、二、三"式机械编号，用观点句做标题；小节长度不要均匀，多数小节平收、不升华；深度≠门槛，每节仍用故事或场景开场。初稿完成后按两份规范自查一遍再交付。

**结构反模板**：动笔前翻看 `wx/` 下最近 2-3 篇 article.md，本篇开场类型、骨架、小标题风格、结尾动作必须与上一篇错开（轮换菜单见 CLAUDE.md"结构反模板"）。小节数量也别固定在 3-5 的同一个数上。

## 红线

- **交付前必须按 `content-review` skill 的公众号一节做合规扫描**（含标题、摘要）。加密内容可科普但禁诱导交易表述；禁利益诱导式转发话术。
- 金融内容文末加风险提示，不构成投资建议。
- 涉政策监管话题只引用公开信息，不做阴谋论式解读。
- 引用数据注明来源。

## 输出

写入 `wx/<YYYY-MM-DD-主题slug>/article.md`，结构：

```markdown
# 标题候选
1. ...
2. ...
3. ...

# 摘要
...

# 正文
...（含小标题与 [配图：...] 标注）
```

如果该主题文件夹已存在，直接更新其中的 article.md。生成后简要说明文章的论证主线。
