# 生产部：初稿 → 修稿 → 定稿再生产

输入：`ideas/` 下一个已通过运营评估的选题文件。如果选题文件没有「运营评估」节、或判定为 ⛔ 暂缓，先提醒补选题环节（`new-idea` / `ops`），除非用户明确要求跳过评估直接生产。用户连选题环节都跳过、直接拿想法要稿的：先补一个最简选题文件（标题/日期/领域/状态/核心观点即可，不做评估）再进阶段一——归档提交和三平台 slug 对照都依赖它。

## 阶段一：初稿生产

1. **读素材库（有则必读）**：检查 `materials/` 下是否有本选题的素材文件夹（可能还是随手起的名，先认领再重命名为与三平台一致的 `YYYY-MM-DD-slug`）。文件夹里的 `notes.md` 和截图全部读完：事实类信息（版本号、指令原话、耗时、翻车细节）以素材为准，不改写成"更整的数"；素材缺关键信息（见 `materials/README.md` 的覆盖清单）就先追问用户，**宁可模糊不编造**。实测类选题没有素材文件夹的，动笔前先提醒用户补素材。
2. **写前查重**：翻看 `xhs/`、`wx/`、`x/` 下最近 2-3 个主题文件夹的成品，确认本篇每个平台的开场类型和骨架与上一篇不同（按 CLAUDE.md「结构反模板」的轮换菜单选），把所选结构写进选题文件的「平台角度」。
3. **三平台文字稿**：依次按 `xhs-post`、`wx-article`、`x-post` 的**文字部分**规范生成（同一会话内直接按其 SKILL.md 的规则写，不必重复调用工具），全部以选题文件为输入，使用**相同的主题 slug** 建文件夹：
   - `xhs/<YYYY-MM-DD-slug>/content.md`
   - `wx/<YYYY-MM-DD-slug>/article.md`
   - `x/<YYYY-MM-DD-slug>/thread.md`

   三个平台不是同一篇文章的删改版，而是同一观点在不同语境下的原生表达。运营评估建议只做部分平台的，按建议来；某平台确实不适合这个选题的，直接说明并建议跳过，不硬写。
4. **本阶段严禁生成任何图片**（不写图片 html、不渲染）。
5. **送审稿部（强制）**：初稿完成后、汇报给用户前，按 `content-review` skill 做全量扫描（合规 + AI 味，范围含标题、标签、封面文案、摘要）。审出问题直接改稿；某平台被判 ⛔ 高风险的，建议跳过或换角度，交用户决定。
6. **汇报**：核心观点、三个平台各自的切入角度差异、文件位置、审稿判定与改动清单。

## 阶段二：修稿循环

等用户对文字稿逐轮提出修改意见，修订对应文件，直到用户**明确表示定稿**（如"定稿""可以了""就这样发"）。

- 修稿期间不生成图片。
- 修改涉及敏感话题表述时，对改动部分即时复扫（`content-review` 对应平台一节），别攒到定稿才发现问题。

## 阶段三：定稿再生产

用户明确定稿后执行：

1. **定稿复扫**：按 `content-review` 快速复扫（修稿循环可能引入新的敏感表述）。
2. **出图**：小红书整套图按 `xhs-post`「整套图生成」章节；公众号封面 + 插图按 `wx-article`「配图流水线」章节。图上文案与定稿正文保持一致。
3. **发布转换**：公众号跑 `md2wechat.py` 生成 `article_wechat.html`（见 `wx-article`「发布转换」节）。
4. **归档推送**：图片交付确认无误后，本选题全部资产提交 git 并推送：

   ```bash
   git add ideas/<选题文件> materials/<主题文件夹> xhs/<主题文件夹> wx/<主题文件夹> x/<主题文件夹>
   git commit -m "选题归档：<选题标题>"
   git push
   ```

   无素材的选题跳过 materials 项；`materials/*/raw/` 已 gitignore，未打码原图不会入库。提交信息用中文一句话说清选题；如本次还改了 skill 或模板，一并提交并在信息里说明。远程为 https://github.com/summerain0401/media（HTTPS + gh 凭证，勿改回 SSH）。
5. **交接运营部**：提醒用户发布当天在 `operations/publish-log.md` 登记（日期/平台/slug/配比类别，可由 `ops` 代记），24 小时后把曝光/互动数据回填台账。

## 中途恢复（常见情况）

修稿和定稿经常发生在与初稿不同的会话里。用户带着某个选题回来改稿或定稿时，直接从对应阶段接续：读选题文件和三平台现稿恢复上下文，不重走前置阶段、不重新评估选题。
