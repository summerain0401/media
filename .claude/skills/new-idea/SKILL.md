# 选题部：提议 → 沉淀 → 运营评估 → 用户决策

本 skill 只负责选题环节，**不生产内容**。流水线全景：

**选题（本 skill）→ 运营评估（ops，本环节内调用）→ 用户决策 → 初稿生产 → 审稿 → 修稿 → 定稿再生产（后四步归 produce 生产部，审稿由 content-review 执行）**

## 第 1 步：沉淀选题

把用户的想法整理成选题文件，写入 `ideas/<YYYY-MM-DD-主题slug>.md`（slug 用简短英文小写连字符，如 `2026-07-10-ai-agent-jobs`）：

```markdown
# <选题标题>

- 日期：YYYY-MM-DD
- 领域：（科技AI / web3 / 金融经济 / 商业财经 / 社会学 / 生活感悟）
- 状态：草稿

## 核心观点
（一句话说清这篇内容的中心论点——没有明确观点的选题先和用户确认角度）

## 目标受众
（谁会关心这个话题，他们的痛点/兴趣点）

## 素材要点
（论据、数据、案例、个人经历——**优先找能讲的故事和场景**，一个好故事胜过三个论点；想法里没有的，主动补充调研或向用户要）

## 平台角度
- 小红书：（切什么角度、什么钩子）
- 公众号：（论证主线）
- X：（单条还是 thread、锋利的立场是什么）
```

如果用户的想法过于模糊（只有话题没有观点），先用一两个问题和用户对齐角度，再继续。

## 第 2 步：运营评估（强制）

按 `ops` skill「职责一：选题评估」对本选题做评估（阶段匹配、配比、系列排期、平台风险预判、精力配比），把结果写进选题文件新增的「运营评估」节：

```markdown
## 运营评估
- 日期：YYYY-MM-DD
- 判定：（✅ 推进 / 🔄 调整后推进 / ⛔ 暂缓）
- 理由：（对照了哪些规划、为什么）
- 建议：（主攻平台 / 发布时机 / 配比归类 / 需跳过的平台）
```

## 第 3 步：汇报，等用户决策

向用户汇报：选题核心观点 + 运营评估的判定与理由。然后**停下来**——是否推进由用户拍板，评估只是运营部的建议：

- 用户说**推进/继续** → 选题文件状态改为「生产中」，按 `produce` skill 进入初稿生产（同一会话直接继续）。
- 用户要求**调整角度** → 修改选题文件，重新过第 2 步评估。
- 用户**放弃/重新提议** → 选题文件状态改为「搁置」，保留在 `ideas/` 备查，等用户的新提议。

## 用户只想存想法时

用户只是想把一个想法记下来、暂不生产的：只做第 1 步，状态标「草稿」，不做运营评估（等将来启用时再评，规划是滚动更新的，提前评会过期）。
