# 新想法 → 三平台内容

用户给出一个想法，本 skill 负责完整流水线：选题沉淀 → 三平台内容生成。

## 流程

### 第 1 步：沉淀选题

先把想法整理成选题文件，写入 `ideas/<YYYY-MM-DD-主题slug>.md`（slug 用简短英文小写连字符，如 `2026-07-10-ai-agent-jobs`）：

```markdown
# <选题标题>

- 日期：YYYY-MM-DD
- 领域：（科技AI / web3 / 金融经济 / 商业财经 / 社会学 / 生活感悟）
- 状态：草稿

## 核心观点
（一句话说清这篇内容的中心论点——没有明确观点的选题先和用户确认角度）

## 目标受众
（谁会关心这个话题，他们的痛点/兴趣点）

## 素材要点
（论据、数据、案例、个人经历——**优先找能讲的故事和场景**，一个好故事胜过三个论点；想法里没有的，主动补充调研或向用户要）

## 平台角度
- 小红书：（切什么角度、什么钩子）
- 公众号：（论证主线）
- X：（单条还是 thread、锋利的立场是什么）
```

如果用户的想法过于模糊（只有话题没有观点），先用一两个问题和用户对齐角度，再继续。

### 第 2 步：生成三平台文字稿（不出图）

**写前查重**：先翻看 `xhs/`、`wx/`、`x/` 下最近 2-3 个主题文件夹的成品，确认本篇每个平台的开场类型和骨架与上一篇不同（按 CLAUDE.md"结构反模板"的轮换菜单选），并把所选结构写进选题文件的"平台角度"。

依次执行 `xhs-post`、`wx-article`、`x-post` 三个 skill 的**文字部分**规范（同一会话内直接按其 SKILL.md 的规则生成，不必重复调用工具），全部以第 1 步的选题文件为输入，使用**相同的主题 slug** 建文件夹：

- `xhs/<YYYY-MM-DD-slug>/content.md`
- `wx/<YYYY-MM-DD-slug>/article.md`
- `x/<YYYY-MM-DD-slug>/thread.md`

三个平台不是同一篇文章的删改版，而是同一观点在不同语境下的原生表达——允许各平台强调不同侧面。

**本步骤严禁生成任何图片**（不写图片 html、不渲染）。

### 第 2.5 步：平台合规审稿（强制）

三平台初稿写完后、汇报给用户前，按 `content-review` skill 的分平台红线逐篇扫描（范围含标题、标签、封面文案、摘要）。审出问题直接改稿，汇报时附每平台判定和改动清单；某平台被判 ⛔ 高风险的，建议跳过或换角度，交用户决定。

### 第 3 步：汇报 + 修稿循环

向用户汇报：选题的核心观点、三个平台各自的切入角度差异、文件位置、平台审稿结果。如果某平台不适合这个选题（比如纯生活感悟不适合发严肃 thread），直接说明并建议跳过，而不是硬写。

然后进入**修稿循环**：等用户对文字稿提出修改意见，逐轮修订对应文件，直到用户**明确表示定稿**（如"定稿""可以了""就这样发"）。修稿期间不生成图片。

### 第 4 步：定稿后出图

用户确认定稿后，先按 `content-review` skill 对定稿做一次快速复扫（修稿循环可能引入新的敏感表述），再执行图片流水线：
- 小红书整套图：按 `xhs-post` 的"整套图生成"章节；
- 公众号封面 + 插图：按 `wx-article` 的"配图流水线"章节。

出图基于定稿后的文字，图上文案与正文保持一致。

### 第 5 步：归档推送

图片交付并确认无误后，把本选题的全部资产提交到 git 并推送：

```bash
git add ideas/<选题文件> xhs/<主题文件夹> wx/<主题文件夹> x/<主题文件夹>
git commit -m "选题归档：<选题标题>"
git push
```

提交信息用中文一句话说清选题；如本次还改了 skill 或模板，一并提交并在信息里说明。远程为 https://github.com/summerain0401/media（HTTPS + gh 凭证，勿改回 SSH）。

## 用户只想要单平台时

如果用户明确只要某一个平台的内容，直接用对应的平台 skill，不走本流程。
