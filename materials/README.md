# 素材库

实测素材的集中存放地。每个选题一个文件夹，生产（`/produce`）初稿前必读——里面的真实细节（版本号、指令原话、带零头的耗时、翻车瞬间、截图）是去AI化的第一原料，有素材绝不编造。

## 目录约定

```
materials/
  <选题文件夹>/
    notes.md      # 口述素材：随手记，不用整理格式（见下）
    *.png|jpg     # 已打码、可直接发布的截图，命名带序号：01-before.png
    raw/          # 未打码的原始截图（已 gitignore，不会推到 GitHub）
```

- **文件夹命名**：素材先于选题存在时随便起个认得出的名（如 `ai-tools-01-workbuddy`）；选题进入生产后，文件夹重命名为与 `xhs/`、`wx/`、`x/` 一致的 `YYYY-MM-DD-slug`，四处同名对照。
- **notes.md 不设格式要求**：口述、碎片、错别字都行。宁可啰嗦别精简——"大概六七分钟""印象里卡了一下"这类毛边正是成稿要的。
- **截图打码**：任何含个人信息的图先处理再放外层；来不及处理的丢 `raw/`，出图阶段再统一打码。

## notes.md 建议覆盖的内容（缺了生产时会被追问）

- 工具版本号、下载渠道、实测日期
- 给 AI 的指令**原话**（一字别改）
- 过程与结果：耗时（带零头）、卡壳、翻车、分错的地方
- 第一反应、超预期的点、**不满意的点**（全是夸 = 商单味，过不了审）
- 与论点无关的现场细节（当时在干嘛、顺手聊到什么）——成稿的"脏细节"来源

## 生产时的使用规则（对 Claude）

1. 初稿动笔前**整个文件夹全部读完**，事实类信息（版本、数字、指令）以素材为准，不得改写成"更整的数"。
2. 素材里没有的具体细节**宁可模糊或问用户，不编造**。
3. 截图按序号对应到成稿的配图位；`raw/` 内容不引用、不外发。
